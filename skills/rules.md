# January OS 组件化宏内核规则

本规则定义 `january_os` 向“组件化宏内核”推进时必须遵守的工程约束。

## 1. 总体模式

- 内核保持**宏内核**：核心子系统仍运行在统一内核地址空间与统一内核映像中。
- 组件化目标是**强边界、弱耦合、显式依赖**，不是把核心能力搬到用户态。
- 所有新增设计默认优先采用：
  - 明确组件职责
  - 明确初始化阶段
  - 明确依赖方向
  - 明确对外稳定接口

## 2. 组件边界

- 每个一级子系统视为一个组件：`arch`、`mm`、`interrupt`、`task`、`fs`、`drivers`、`syscall`、`virt`、`sync`。
- 组件必须优先通过**组件入口模块**暴露能力，不要默认跨模块直接引用深层实现。
- 避免在 `mod.rs` 中使用大范围 `pub use ...::*` 扁平导出内部实现；应优先导出稳定 façade。
- 运行时行为、状态统计、初始化入口应从组件入口模块可见。

## 3. 依赖方向

推荐依赖方向：

- `arch` / `libs` / `sync`
- → `mm` / `interrupt`
- → `task`
- → `fs` / `drivers` / `virt`
- → `syscall`
- → `shell` / `tests`

约束：

- 低层组件不得反向依赖高层组件。
- `syscall` 只能编排已有组件能力，不应承载底层资源管理实现。
- `drivers` 应依赖 `mm/interrupt/pci` 等下层能力，不得直接塑造高层策略。
- `tests` 允许穿透，但不得把测试辅助逻辑泄漏回运行时代码。

## 4. 初始化模型

- 所有核心组件必须声明初始化阶段：`early` / `core` / `late`。
- 组件初始化必须声明依赖；禁止依赖只存在于注释或默认顺序中。
- 启动路径应统一通过组件注册/运行器编排，而不是不断追加匿名顺序调用。
- 组件初始化日志必须包含：组件 ID、阶段、依赖、结果。

## 5. 组件接口规范

每个组件至少应具备：

- `init_*` 或等价统一入口
- 最小状态/统计接口（如 `stats()`）
- 清晰的错误边界
- 可选的 `dump_state()` / `trace_*()` 调试入口

新增组件接口时：

- 优先暴露 trait、descriptor、report、context 等稳定结构
- 避免把内部锁、内部容器、裸全局状态直接暴露给外部组件
- 跨组件传递上下文时，优先显式结构体，不依赖隐式全局变量

## 6. 驱动组件规则

- `drivers/` 不是杂项目录；每类驱动必须有统一入口和初始化报告。
- 总线发现、设备匹配、驱动初始化应分层：
  - bus/core
  - device match
  - driver init
- 驱动组件应通过 `drivers::init_all()` 或等价 façade 暴露组合能力，避免启动器逐个点名内部模块。

## 7. 文件系统与任务规则

- `fs` 必须区分：
  - VFS 核心
  - 进程文件描述符运行时
  - syscall glue
  - backing / mmap 适配
- `task` 必须区分：
  - 调度与上下文切换
  - 进程/线程元数据
  - exec/fork/wait 生命周期
- 这两个组件可以协作，但不得彼此吞并职责。
- `task/process/exec.rs` 属于**进程生命周期组件**，不得继续放回 `task/` 根层或调度器实现中。
- `task/scheduler/` 不得承载 `fork/exec/wait/exit` 的主实现逻辑。
- `syscall/handlers/process.rs` 应保持薄适配层：参数解析、errno 映射、调用 `task/process/*` façade；不得长期承载 `fork/wait/exit` 主逻辑。

## 8. 架构隔离

- 架构专属实现必须放在：
  - `boot/<arch>/`
  - `kernel/src/arch/<arch>/`
  - `kernel/src/**/arch/<arch>/`
- 通用组件可以定义 trait/接口，但不得在通用目录硬编码 x86_64 细节，除非带明确临时说明。

## 9. 文档与技术债

- 任何“组件化但只做到一部分”的实现，都必须在 `docs/progress/tech-debt.md` 记录剩余差距。
- 架构文档必须同步真实代码状态，不能只保留理想设计。
- 新规则落地时，应同步更新相关 docs / skills，而不是只改代码。

## 10. 完成标准

一个子系统可被称为“符合组件化宏内核规则”，至少满足：

- 有清晰组件入口
- 初始化阶段与依赖显式可见
- 对外 API 明显少于内部实现面
- 依赖方向符合分层约束
- 文档能说明其职责、边界与剩余债务
