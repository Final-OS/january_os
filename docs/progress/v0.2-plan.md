# v0.2 分批实施计划

本文用于冻结 `v0.2` 范围，并定义每一批任务的可验收标准。

---

## 目标范围（Scope）

`v0.2` 聚焦五条主线：

1. 进程管理（创建、执行、退出、回收）
2. 调度器增强（基础可用 + 多核可观测）
3. 系统调用扩展（Linux ABI 兼容优先）
4. IPC 最小闭环（信号/管道基础能力）
5. 同步原语演进（从全系自旋向可阻塞等待过渡）

### v0.2 版本定位

- `v0.2` 的核心任务是打稳内核基础能力，使 `v0.3` 的 VFS/块设备/用户空间主线可在现有内核能力上连续推进。
- `v0.2` 关注“可运行 + 可验证 + 可扩展边界”，不要求在本版本完成所有长期目标（如 EEVDF、全量 syscall Linux 兼容）。

### v0.2 必须完成

- 进程创建链路：`clone/fork/vfork` 最小可用语义
- 进程执行链路：`execve` 最小可用闭环
- `wait4` 事件链路闭环（含停止/继续事件来源）
- 信号基础能力：`SIGCHLD/SIGTERM/SIGKILL/SIGSTOP/SIGCONT`
- IPC 最小闭环：signal + pipe 最小可用语义（含错误路径）
- 调度器基础增强：可观测性、多核基础负载均衡
- 核心 syscall 扩展：补齐用户态可运行所需最小集合

### v0.2 可延期（明确不阻塞）

- EEVDF / 完整实时调度策略（跨版本任务，不绑定 v0.2）
- 全量 Linux syscall 覆盖与完备兼容（跨版本任务，不绑定 v0.2）
- 完整文件系统/网络栈
- 图形栈与桌面能力

## 分批计划（Batches）

### Batch 1：范围冻结与验收口径

**目标**
- 固化 `v0.2` 必须项与延期项
- 建立统一验收标准

**产出**
- 本文档
- `docs/progress/overview.md` 的入口与状态同步

**验收条件**
- 文档完成并可用于后续批次打勾追踪

### Batch 2：进程创建链路（clone/fork）

**目标**
- 打通子进程创建与父子关系维护
- 明确 PID/TID/PGID 继承规则

**验收条件**
- 能创建并回收子进程
- 错误路径返回正确 errno（如 `-EINVAL/-ECHILD`）

### Batch 3：执行链路（execve + 用户态切换）

**目标**
- 打通最小 `execve` 路径与用户态切换

**验收条件**
- 用户程序能被加载、运行、退出

### Batch 4：信号与 wait4 事件闭环

**目标**
- stop/continue/exit 事件可被 wait 系列一致观测

**验收条件**
- `WUNTRACED/WCONTINUED/WNOHANG` 行为与 Linux ABI 约定一致

### Batch 5：系统调用扩展（v0.2 最小集）

**目标**
- 以用户态可运行为目标补齐 syscall 子集

**建议优先级**
- `read/open/close`
- `mmap/munmap`

**验收条件**
- 最小用户程序具备 I/O + 内存映射能力
- v0.2 范围内已实现 syscall（`read/write/open/close/mmap/munmap/fork/clone/vfork/execve/wait4/exit`）具备完整语义与错误路径覆盖。
- 与 Linux 行为对齐：参数校验、errno、边界条件、权限/状态转换语义一致（允许在文档中明确列出差异并附测试）。

### Batch 6：调度器增强

**目标**
- 提升多核场景下公平性与可观测性

**验收条件**
- 无明显饥饿
- 多核运行下基础负载均衡生效

### Batch 7：IPC 最小闭环

**目标**
- 交付 v0.2 范围内最小可用 IPC 能力，并与进程/调度联动。

**验收条件**
- `signal` 路径与 `wait4` 事件链路保持一致（stop/continue/exit 可观测）。
- `pipe` 具备最小可用读写语义与错误路径（如 `EBADF/EPIPE`）覆盖。
- 测试可通过 `test` 命令独立触发并输出步骤级日志。

### Batch 8：Sync 子系统演进（阻塞原语最小闭环）

**目标**
- 在保留现有自旋原语稳定性的前提下，补齐与调度器协作的阻塞等待能力。
- 为后续高并发场景建立可验证的同步基础能力。

**验收条件**
- `Mutex/Semaphore` 至少具备一种可阻塞等待路径（非纯忙等），并通过回归验证。
- 新增 `CondVar` 最小实现（`wait/signal/broadcast`）并提供生产者-消费者测试用例。
- 死锁检测/调试检查支持构建期开关（调试构建默认开，发布构建可降开销）。
- 中断上下文使用路径保持 IRQ 安全（`IrqSpinLock/IrqMutex` 约束不回退）。

### Batch 9：回归测试与文档收口

**目标**
- 固化回归流程，形成 `v0.2` 发布检查单

**验收条件**
- QEMU + VMware 启动回归通过
- 核心进程/调度/syscall 场景有可重复测试步骤

## v0.2 发布阻塞项（Blockers）

### B1：syscall 入口栈切换硬化（阻塞）

**问题**
- `syscall_entry` 不能在用户栈上执行内核 `push/call`，必须先切换到内核栈。

**验收条件**
- 入口路径改为“先切内核栈，再保存寄存器并分发”。
- 异常与回退路径不再依赖用户栈有效性。

**状态**
- 已完成：入口已切换为 `swapgs + gs` per-CPU 栈槽位路径。

### B2：syscall 覆盖口径与文档一致性（阻塞）

**问题**
- 当前 `x86_64` 实际仍是“最小可运行子集”，与“功能完备 + Linux 兼容”目标之间有差距。

**验收条件**
- 进度文档与实际实现一致。
- 覆盖范围变化（新增/未实现）均附带回归说明。
- 已实现 syscall 的行为差异（若有）必须文档化并附可重复测试。

**状态**
- 已完成：已按当前实现同步文档口径并补回归项。

### B3：syscall 分发可维护性（非阻塞）

**问题**
- 手写 `match` 随 syscall 增长维护成本上升。

**验收条件**
- 在不影响现有行为前提下，评估并落地代码生成或宏化方案（可延期到后续版本）。

## v0.2 后续优化积压（非阻断）

以下条目不阻塞 `v0.2` 发布，但应纳入后续迭代的明确里程碑。

### O1：Mm 锁粒度优化（并发扩展）

**目标**
- 从当前大锁策略逐步演进到更细粒度锁模型（如 `RwLock` 或分层锁）。
- 降低 `mmap/munmap/page fault` 并发路径上的锁竞争与串行化开销。

**建议阶段**
1. 先拆分“只读查询路径”和“写修改路径”。
2. 再评估 `VMA tree` 与统计字段的锁分离。
3. 最后补充并发压测与锁顺序文档。

**验收标准**
- 高并发内存映射场景无死锁、无数据竞争回归。
- `test mm mmap`、`test mm` 稳定通过。
- 关键路径锁等待时间有可观测下降（日志或计数器）。

### O2：OOM 处理策略增强（回收与淘汰）

**目标**
- 从“直接返回失败”升级为“优先回收，再决策失败/淘汰”的分层策略。
- 建立可解释的内存压力处理路径，避免随机失败行为。

**建议阶段**
1. 引入基础 reclaim 路径（匿名页/缓存页回收框架）。
2. 在 reclaim 无效时接入最小 OOM 选择器（可先按简单分数规则）。
3. 增加 OOM 观测日志与失败分类。

**验收标准**
- 人工内存压力场景下，系统行为可预测且可复现。
- OOM 路径日志可定位“回收失败原因/淘汰决策原因”。
- 无新增 double-free、use-after-free 类回归。

### O3：TLB Shootdown 策略优化（Lazy/Batch）

**目标**
- 在保证一致性的前提下，减少跨核 shootdown 同步等待开销。
- 将当前同步等待模型演进为延迟刷新或批量刷新策略。

**建议阶段**
1. 先引入可配置开关与统计计数（IPI 次数、超时次数、批处理命中率）。
2. 再实现按 CPU/地址区间聚合的批量刷新。
3. 最后评估惰性刷新窗口与一致性边界。

**验收标准**
- `munmap` 跨核可见性回归持续通过。
- 压测下 TLB shootdown 超时告警显著下降或可控。
- 不出现 stale mapping 导致的权限/一致性错误。

### O4：SMP 调度器成熟化（Per-CPU Runqueue 后续）

**目标**
- 在当前 per-CPU runqueue + 基础 work-stealing 之上，补齐生产可用的多核调度能力。
- 明确“可观测、可调优、可验证”的调度质量标准。

**建议阶段**
1. 引入调度可观测指标（每 CPU 队列长度、窃取成功率、迁移次数、空转占比）。
2. 完善 work-stealing 策略（受害者选择、批量窃取、跨核迁移节流）。
3. 增加 affinity/拓扑感知策略（优先本核、NUMA/缓存局部性约束）。
4. 评估从 RR 向更先进策略迁移（如 EEVDF），并保留回退开关。

**验收标准**
- 4 核及以上场景下，调度无明显单核热点与长期饥饿。
- `test task`、`test task usermode`、核心回归在 SMP 环境稳定通过。
- 调度路径关键指标可在 shell/日志中观测并用于问题定位。

### O5：IOMMU/DMA 子系统成熟化（驱动可用）

**目标**
- 在现有 IOMMU/SWIOTLB 与 DMA API 基础上，补齐设备侧可用性与隔离能力。
- 将当前“可运行”状态推进到“可验证、可观测、可回归”的驱动基础设施。

**建议阶段**
1. 补齐硬件后端能力边界与错误路径（VT-d 失败回退、映射失败分类、统计暴露）。
2. 建立设备域/隔离策略与驱动接入约束（按设备能力选择直通、IOMMU 映射或 SWIOTLB）。
3. 增加 DMA 一致性与边界回归（32-bit 设备高地址访问、跨页/非对齐、重复 map/unmap）。
4. 完成典型驱动链路联调（至少一类块设备或网卡 DMA 路径）。

**验收标准**
- `iommu.mode=auto/on/off` 三种模式下启动行为与日志符合预期。
- DMA 映射/解映射失败可定位（明确 errno/日志原因），无已知内存泄漏与 double-free。
- 至少一个真实设备 DMA 路径在 IOMMU 与 SWIOTLB 回退场景都可通过回归。

### O6：syscall Linux 兼容收口（跨版本）

**目标**
- 将已实现 syscall 从“最小可运行”逐步收口到“功能完备 + Linux 兼容”。

**建议阶段**
1. 按 syscall 分组整理兼容矩阵（参数、返回值、errno、边界条件、并发语义）。
2. 补齐缺失语义与错误路径（含无效输入、异常输入、边界输入、恢复路径）。
3. 增加逐 syscall 回归用例与日志模板，形成可追踪基线。
4. 对暂未对齐项提供显式差异清单与版本归属说明。

**验收标准**
- 当前版本已实现 syscall 均有“主路径 + 关键分支 + 失败路径 + 恢复路径”覆盖。
- Linux 兼容差异可量化、可追踪，且不影响 v0.2 发布目标的项已明确标注。
- `test task`、`test mm mmap`、相关 syscall 回归在 SMP 环境下稳定通过。

## 跨版本长期任务（不绑定 v0.2）

### L1：EEVDF 调度器与实时调度完善

- 范围：调度实体模型、虚拟截止时间、公平性与低延迟策略、SMP 场景稳定性。
- 版本归属：`v0.4.0`（在 `v0.3.0` 完成文件系统/用户空间基础后推进调度策略升级）。

### L2：syscall 全量完备实现与 Linux 兼容

- 范围：全量 syscall 覆盖、语义/errno/边界行为对齐、差异清单清零或显式豁免。
- 版本归属：`v1.0.0`（作为发布目标能力收口项，跨版本持续补齐并回归）。
