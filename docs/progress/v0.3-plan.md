# v0.3 分批实施计划

本文用于冻结 `v0.3` 范围，并定义每一批任务的可验收标准。

---

## 目标范围（Scope）

`v0.3` 聚焦于构建完整的用户空间运行环境，使内核能够加载和执行真实用户程序：

1. **VFS 虚拟文件系统** - 统一文件/设备抽象层
2. **块设备层** - virtio-blk 主链路 + 多控制器扩展（virtio-scsi/PVSCSI/NVMe/AHCI）
3. **FAT32 文件系统** - 简单可靠的只读/读写文件系统
4. **用户空间基础** - ELF 加载完善 + argv/envp/auxv + 基础 C 库
5. **procfs/sysfs** - 内核状态暴露与调试接口

### v0.3 版本定位

- `v0.3` 的核心任务是打通"磁盘 → 文件系统 → 用户程序"链路
- 使用户能够在 shell 中运行从磁盘加载的真实程序
- 为 v0.4 的网络栈和高级调度提供稳定的用户空间基础

### 范围冻结（2026-03-04）

- `ext4`（只读）是 `v0.3` 必选项，不下放子版本
- `v0.3.0` 只承诺“主链路可运行”，非阻断项下放 `v0.3.1/0.3.2`
- 主链路定义：块设备 + 分区 + VFS + FAT32/ext4 只读 + VFS `execve` + 最小目录/路径 syscall

### 严格审计口径（2026-03-19）

- 本页默认区分 `v0.3.0` 与整个 `v0.3.x`：前者只看主链路是否可运行，后者包含子版本债务偿还。
- 当前结论是：`v0.3.0` 主链路已基本完成并进入收口；`v0.3.1/0.3.2` 仍承接 `procfs`、扩展 syscall、多控制器块设备、动态链接器与 `sysfs`。
- 运行时口径必须写实：当前 `/` 仍固定为 `initramfs`，磁盘文件系统通过手工 `mount` 或 `/mnt/*.img` 镜像进行验证，不应表述为“磁盘 rootfs 已完成”。

### v0.3 必须完成

- 块设备驱动：virtio-blk 完整读写支持
- 块设备抽象：BlockDevice trait + MBR/GPT 分区解析
- VFS 核心：mount/umount + inode/file + 路径解析
- FAT32 文件系统：只读挂载 + 目录遍历 + 文件读取
- ext4 文件系统：只读挂载 + 文件读取（基础）
- 用户空间完善：argv/envp/auxv 栈帧 + VFS ELF 加载
- 主链路 syscall：lseek/getdents64/chdir/getcwd + dup/dup2/fcntl（最小子集）
- 集成验收：shell 可运行 `ls/cat` 并执行磁盘 ELF 程序

### 下放到 v0.3 子版本（不阻塞 v0.3.0）

- `v0.3.1`：procfs 基础、`statfs/fstatfs/dup3`、open flag 扩展、virtio-scsi 最小可用链路
- `v0.3.2`：动态链接器最小集、sysfs、ext4 读取能力增强（htree/更多特性）、PVSCSI/NVMe/AHCI 最小可用链路
- 延续到 `v0.4`：可写 ext4、完整 POSIX 文件语义、initramfs

### 当前块设备驱动缺口清单（2026-03-04）

- 设备类型覆盖不足：当前仅 `virtio-blk`，缺 `virtio-scsi`、`PVSCSI`、`NVMe`、`AHCI`。
- 统一注册与枚举不足：缺“控制器 -> 命名空间/LUN -> 分区设备”的统一挂接流程。
- 请求层能力不足：缺统一请求队列、合并策略、超时重试、控制器 reset 恢复路径。
- 语义能力不足：`flush/fua/barrier`、只读介质、可移除介质、容量变化事件处理不完整。
- 可观测性不足：缺按驱动维度的统计与故障定位（超时、重置、介质错误）。
- 测试矩阵不足：缺 QEMU/VMware 跨控制器一致性测试与异常注入回归。

## 分批计划（Batches）

### Batch 1：块设备抽象与 virtio-blk 驱动

**目标**
- 定义通用 `BlockDevice` trait
- 实现 virtio-blk 驱动（QEMU 兼容）
- 支持基础读写操作

**关键接口**
```rust
pub trait BlockDevice: Send + Sync {
    fn block_size(&self) -> u32;
    fn block_count(&self) -> u64;
    fn read_block(&self, lba: u64, buf: &mut [u8]) -> Result<(), BlockError>;
    fn write_block(&self, lba: u64, buf: &[u8]) -> Result<(), BlockError>;
}
```

**产出文件**
- `kernel/src/drivers/block/mod.rs` - BlockDevice trait
- `kernel/src/drivers/block/virtio_blk.rs` - virtio-blk 实现

**验收条件**
- QEMU 环境下 virtio-blk 设备成功初始化
- 可读写单个扇区并校验数据完整性
- `test block virtio` 回归通过

### Batch 2：分区表解析

**目标**
- 支持 MBR 分区表解析
- 支持 GPT 分区表解析（基础）
- 为每个分区创建 BlockDevice 包装

**关键结构**
```rust
pub struct Partition {
    pub index: u32,
    pub start_lba: u64,
    pub block_count: u64,
    pub part_type: PartitionType,
}

pub struct PartitionedDevice {
    device: Arc<dyn BlockDevice>,
    partitions: Vec<Partition>,
}
```

**产出文件**
- `kernel/src/drivers/block/partition.rs`
- `kernel/src/drivers/block/mbr.rs`
- `kernel/src/drivers/block/gpt.rs`

**验收条件**
- 正确解析 QEMU virtio-blk 的 MBR/GPT 分区
- `test block partition` 回归通过

### Batch 3：VFS 核心抽象

**目标**
- 定义 VFS 核心接口（SuperBlock, Inode, File, Dentry）
- 实现 mount/umount 管理
- 路径解析与命名空间

**关键接口**
```rust
pub trait FileSystem: Send + Sync {
    fn name(&self) -> &str;
    fn root(&self) -> Arc<dyn Inode>;
    fn sync(&self) -> Result<(), i32>;
}

pub trait Inode: Send + Sync {
    fn ino(&self) -> u64;
    fn mode(&self) -> InodeMode;
    fn size(&self) -> u64;
    fn read_at(&self, offset: u64, buf: &mut [u8]) -> Result<usize, i32>;
    fn lookup(&self, name: &str) -> Result<Arc<dyn Inode>, i32>;
    fn readdir(&self, cb: &mut dyn FnMut(&DirEntry) -> bool);
}

pub trait File: Send + Sync {
    fn inode(&self) -> Arc<dyn Inode>;
    fn pos(&self) -> u64;
    fn seek(&mut self, whence: SeekWhence, offset: i64) -> Result<u64, i32>;
}
```

**产出文件**
- `kernel/src/fs/vfs/mod.rs` - VFS 核心导出
- `kernel/src/fs/vfs/inode.rs` - Inode trait
- `kernel/src/fs/fd/file.rs` - File trait
- `kernel/src/fs/vfs/mount.rs` - mount 管理
- `kernel/src/fs/vfs/path.rs` - 路径解析

**验收条件**
- 可挂载/卸载文件系统
- 路径解析正确处理 `.` `..` 和绝对/相对路径
- `test vfs` 回归通过

**验收条件**

- 可读取文件内容并校验
- `test fs fat32` 回归通过

### Batch 4B：ext4 文件系统（只读，v0.3 必选）

**目标**
- 解析 ext4 超级块与组描述符（最小集）
- 实现 extent-based 文件读取（只读）
- 实现基础目录遍历并接入 VFS

**产出文件**

**验收条件**
- 成功挂载 ext4 格式镜像（只读）
- 可读取根目录和目标文件内容
- `test fs ext4` 回归通过

### Batch 5：VFS syscall 接入

**目标**
- 将现有 `fs::open/read/close` 替换为 VFS 后端
- 实现 `lseek/getdents/statfs` 等 syscall
- 更新 per-process fd 表以支持 File trait 对象

**关键改动**
- `OpenFile` 从 enum 改为 `Arc<dyn File>` + 元数据
- `sys_open` 调用 `vfs::open(path, flags)`
- `sys_read` 调用 `file.read_at(pos, buf)`
- `sys_lseek` 新增实现

**验收条件**
- 现有 `open/read/close` 测试继续通过
- `lseek` 功能正确
- 管道和静态文件后端继续工作

### Batch 6：ELF 加载完善

**目标**
- 从 VFS 加载 ELF 文件（替代静态文件后端）
- 实现 argv/envp/auxv 栈帧构建
- 支持执行磁盘上的用户程序

**关键改动**
- `execve` 从 `fs::read_static_file` 改为 `vfs::open + read`
- 栈布局：
  ```
  [padding for 16-byte alignment]
  [auxv entries]
  [envp pointers]
  [argv pointers]
  [argc]
  ```

**产出文件**
- `kernel/src/task/process/exec.rs` - 更新加载逻辑
- `kernel/src/task/stack.rs` - 新增栈帧构建

**验收条件**
- 可执行 FAT32 分区上的 ELF 程序
- 程序正确接收 argc/argv/envp
- `test task usermode` 更新并通过

### Batch 7：procfs 基础实现

**目标**
- 挂载 `/proc` 文件系统
- 暴露 `/proc/self`, `/proc/[pid]/`, `/proc/cpuinfo`, `/proc/meminfo`

**关键结构**
```rust
pub struct Procfs {
    pid: Option<Pid>,
}

pub struct ProcInode {
    fs: Arc<Procfs>,
    entry: ProcEntry,
}

enum ProcEntry {
    SelfLink,
    PidDir(Pid),
    Cmdline(Pid),
    Status(Pid),
    CpuInfo,
    MemInfo,
}
```

**产出文件**
- `kernel/src/fs/backing/procfs/mod.rs`
- `kernel/src/fs/backing/procfs/inode.rs`

**验收条件**
- `/proc/self` 正确指向当前进程
- `/proc/cpuinfo` 显示 CPU 信息
- `/proc/meminfo` 显示内存信息
- `cat /proc/cpuinfo` 在 shell 中可用

### Batch 8：用户空间集成测试

**目标**
- 创建可启动的磁盘镜像（含 FAT32 + 用户程序）
- 端到端测试：启动 → 挂载 → 执行程序
- 编写简单的 hello world 用户程序

**产出**
- `target/user_disk.img` - 可启动磁盘镜像
- `userland/hello/` - 简单用户程序
- 集成测试脚本

**验收条件**
- 从磁盘启动并挂载 FAT32 分区
- 执行 hello world 程序输出正确
- `make test-integration` 通过

### Batch 9：文档与回归收口

**目标**
- 更新 API 文档
- 补充 VFS/FAT32 实现文档
- 回归测试覆盖所有新增功能

**验收条件**
- 文档与实现一致
- 所有 `test block/vfs/fat` 回归通过
- QEMU + VMware 启动验证

### Batch 10：多控制器块设备扩展（v0.3.1/v0.3.2）

**目标**
- `v0.3.1`：接入 `virtio-scsi`（最小单队列/LUN0 主链路）。
- `v0.3.2`：接入 VMware `PVSCSI`、`NVMe`、`AHCI`（最小识别 + 读写主链路）。
- 将新控制器统一接入 `BlockDevice` 与分区层，确保对 VFS 透明。

**建议产出文件**
- `kernel/src/drivers/block/virtio_scsi.rs`
- `kernel/src/drivers/block/pvscsi.rs`
- `kernel/src/drivers/block/nvme.rs`
- `kernel/src/drivers/block/ahci.rs`
- `kernel/src/drivers/block/scsi/`（公共 SCSI 命令与错误码最小封装）

**验收条件**
- `virtio-scsi`：QEMU 环境识别磁盘并通过 `test block virtio-scsi`。
- `PVSCSI`：VMware 环境识别磁盘并通过 `test block pvscsi`。
- `NVMe/AHCI`：QEMU 环境分别识别并通过基础读写回归。
- 统一回归：`test block` 包含 `virtio-blk/virtio-scsi/pvscsi/nvme/ahci` 子集并可按环境跳过。

## v0.3 细分任务（执行清单）

以下细分以“先打通主链路，再补齐 syscall 与可观测性”为原则，按依赖顺序推进。

### Phase A：Batch 2 分区解析（建议 1 周）

- A1: 新增 `Partition` / `PartitionedDevice` 结构并接入 `kernel/src/drivers/block/mod.rs`
- A2: 实现 MBR 解析（主分区 4 项、扩展分区可先不支持）
- A3: 实现 GPT 解析（Header + Entry Array + CRC 校验最小集）
- A4: 为分区导出 `read_block/write_block` 偏移包装（LBA 平移）
- A5: 新增 `test block partition`，覆盖正常镜像、无效签名、越界分区

**Phase A DoD**
- `make build`
- `make run`
- `test block partition`

### Phase B：Batch 3 VFS 核心（建议 1.5 周）

- B1: 建立 `kernel/src/fs/{vfs,fd}/` 目录与 `FileSystem/Inode/File/DirEntry` 最小 trait
- B2: 实现 mount 表与 `mount/umount`（只支持单命名空间）
- B3: 实现路径解析（绝对/相对路径 + `.` + `..`）
- B4: 提供 VFS 统一入口：`open/read/close/stat/readdir`（内部仍可桥接旧静态后端）
- B5: 新增 `test vfs`，覆盖路径解析、挂载点切换、错误码一致性

**Phase B DoD**
- `make build`
- `make run`
- `test vfs`

### Phase C：Batch 4 + ext4 + Batch 5（双文件系统只读 + VFS syscall，建议 2 周）

- C1: 新增 `kernel/src/fs/backing/fat/`，实现 BPB/FSInfo 解析
- C2: FAT32 目录遍历（已补齐短文件名 + LFN 读取）
- C3: 新增 `kernel/src/fs/backing/ext4/`，实现 superblock/group desc/extent 的只读文件读取
- C4: 将 FAT32/ext4 同时接入 VFS 挂载层（至少支持各自根目录遍历与文件读取）
- C5: 将 `open/read/close` 从静态后端切换到 VFS
- C6: 新增主链路 syscall：`lseek/getdents64/chdir/getcwd/dup/dup2/fcntl`（最小子集）
- C7: 新增 `test fs fat32`、`test fs ext4`、`test syscall fs`（重点覆盖目录遍历与文件偏移）

**Phase C DoD**
- `make build`
- `make run`
- `test fs fat32`
- `test fs ext4`
- `test vfs`
- `test all`

### Phase D：Batch 6 + Batch 8（用户空间加载完善 + 主链路集成，建议 1.5 周）

## 风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 分区+VFS 接口边界不清晰 | 重复改动，返工成本高 | 先冻结 `BlockDevice`/`File` 最小接口，再进入 FAT32 |
| ext4 解析复杂度高 | 可能拖慢主链路收口 | 先限定只读特性集（superblock/extent/基础目录），高级特性下放 v0.3.2 |
| FAT32 规范复杂 | 实现周期长 | 先只读，限制支持的 FAT 类型（仅 FAT32） |
| VFS 设计过度 | 实现复杂 | 参考 Linux minix fs 简化，不追求完整 POSIX |
| ELF 栈帧兼容性 | 用户程序运行失败 | 参考 Linux x86_64 ABI 规范，添加测试用例 |
